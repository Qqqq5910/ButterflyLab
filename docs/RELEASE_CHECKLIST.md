https://github.com/Qqqq5910/ButterflyLab. No deployment or paid calls are authorized.

- Frontend build passed; Lucide directive and 500 kB bundle advisory warnings.

- Browser: Run Demo, baseline, five-seed A/B information intervention,

- Compact research evidence was checked against the original source hash,
  configurations, paired seeds, coverage outcomes and actual network degrees.
- Rule/Mock controls and one historical connectivity action replay are verified.
  A connectivity action is not a completed real LLM society experiment.

## Publication procedure

1. Scan public allowlist and built frontend. Stop on serious findings.
2. Confirm target remote is empty before initializing/staging the initial commit.
3. Stage the reviewed allowlist only; inspect staged paths and sizes.
4. Run repository hygiene on the index and, after commit, all Git history.
5. Push main without force; inspect actual hosted CI and fix failures.
6. Tag the verified commit v0.1.0; publish Release with honest limitations.
7. Inspect remote README, image loads, license, CI, tag and Release.
8. Record final evidence in RELEASE_V0.1.0_REPORT.md.

Known limits: Linux/macOS launcher not locally verified; no paid multi-seed LLM
research; finite simulated populations and approximately controlled network density.
Security scans are bounded checks, not proof of absence of every possible secret.
